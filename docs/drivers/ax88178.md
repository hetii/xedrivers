# ax88178: ASIX AX88178

Directory: `src/drivers/ax88178/` · `0b95:1780` and the adapters built on it · USB
2.0 gigabit Ethernet

The older ASIX protocol, one vendor request per operation, with an external PHY
(Marvell 88E1111, Realtek RTL8211CL or another) reached through software MII.
Shared ASIX code (vendor requests, the configuration descriptor, MII and its
speed resolution) is in `src/drivers/common/asix/`, with ax88179.

**Written without the card (2026-11-04)**, from Linux `asix_devices.c` and
`asix_common.c`, checked against CUsbEnet's `Ax88178.cpp`. Not yet run on hardware.

## How it works

1. The configuration descriptor gives the bulk IN, bulk OUT and interrupt IN;
   SET_CONFIGURATION.
2. `ax88178_bind`: the MAC address, the PHY's address, a software reset.
3. `ax88178_reset`: the EEPROM's word 0x17 says which PHY and LED mode; the PHY is
   powered up through GPIO 1 as that word asks and its id read back; the MAC's
   PHY interface selected and reset; the PHY's own set-up (Marvell: RGMII delays;
   RTL8211CL: its page-5 write); a PHY reset with autonegotiation, 10/100/1000
   and pause advertised; the medium mode; the MAC address written back; receive
   started, promiscuous (the console's address is not the card's).
4. The link: the interrupt pipe (byte 2, bit 0) and the PHY polled every second
   while down; speed and duplex resolved from the MII registers, the medium mode
   set for them.
5. Receive: transfers of up to 2048 bytes (MFB 2048, as Linux and CUsbEnet run
   it), a stream of frames each behind a 4-byte header, a frame or header
   continuing into the next transfer (`ax88178_frames.c`, tested on the host).
   Transmit: one frame a transfer behind its header, 4 padding bytes when it
   would end on a USB packet boundary.

Matched ids: ASIX `0b95:1780`; Billionton `08dd:0114`, Buffalo `0411:006e`,
Sitecom `0df6:0056`, `0df6:061c`, Logitec `0789:0160`, Linksys `1737:0039`, IO-DATA
`04bb:0930`, Belkin `050d:5055`, ABOCOM `14ea:ab11`.

`tools/xectl.py status` shows the `ax178` line: the EEPROM word, the PHY's address
and id, BMSR / LPA / STAT1000 at the last link check, the medium mode and the
counters.

## Issues

- **Not run on hardware yet.** The device's bring-up step (`slot` line) says where
  a card stopped; the `ax178` line what its PHY reported.
- A PHY other than Marvell or RTL8211CL gets only the generic reset and
  advertisement, as in Linux.
- USB 2.0 and 2048-byte receive transfers: below the faster cards, at most what the
  console's USB carries (about 28 MB/s in, 24 MB/s out, see
  [xedrivers.md](../xedrivers.md)).
