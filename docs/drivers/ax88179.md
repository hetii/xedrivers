# ax88179: ASIX AX88179 / AX88178A (AX88179A/B recognised)

Directory: `src/drivers/ax88179/` · `0b95:1790`, `0b95:178a` and the adapters built
on them · USB gigabit Ethernet

ASIX's own protocol: vendor control requests for the MAC and PHY registers, frames
in ASIX's bulk format. Shared ASIX code (vendor requests, the configuration
descriptor, MII) is in `src/drivers/asix/`, with ax88178.

**Written without the card (2026-11-04)**, from Linux `ax88179_178a.c` and
CUsbEnet's `Ax88179x_178A_772D.cpp`. Not yet run on hardware.

## How it works

1. The configuration descriptor gives the interface's bulk IN, bulk OUT and
   interrupt IN; SET_CONFIGURATION.
2. `ax88179_reset`: PHY power (PHYPWR_RSTCTL), the clocks (CLK_SELECT), auto-detach
   if the EEPROM asks for it, the MAC address from NODE_ID, the bulk-in
   aggregation, the pause water levels, no checksum offload (xnet's frames carry
   their own), RX_CTL started and promiscuous (the console's address is not the
   card's), the medium mode, EEE off, autonegotiation restarted.
3. The link: the interrupt pipe's status (bit 16), and the PHY polled every
   second while it is down. On a change the worker reads the PHY's speed and sets
   the medium mode and the bulk-in aggregation for it (`ax88179_link_reset`).
4. Receive: each transfer holds several frames, the metadata at its end
   (`ax88179_frames.c`, tested on the host). Transmit: one frame a transfer
   behind an 8-byte header, as Linux does; CUsbEnet found the multi-frame format
   unreliable on the AX88179.

Matched ids: ASIX `0b95:1790` and `0b95:178a`; Cypress `04b4:3610`, D-Link
`2001:4a00`, Sitecom `0df6:0072`, Samsung `04e8:a100`, Lenovo `17ef:304b`, Belkin
`050d:0128`, Toshiba `0930:0a13`, MCT `0711:0179`, Allied Telesis `07c9:000e`,
`000f`, `0010`.

`tools/xectl.py status` shows the `ax179` line: product, bcdDevice, the EEPROM word,
the PHY status, medium mode, USB speed, link checks and the frame counters.

## Issues

- **Not run on hardware yet.** The device's bring-up step (`slot` line) says
  where a card stopped; the `ax179` line what it reported.
- **AX88179A/B** (`0b95:1790`, bcdDevice 2.00) is a different register set
  (CUsbEnet's `CAx179AFamily`): recognised and stopped at step 6 (`AX179_STEP_179A`)
  until it is written.
- At most what the console's USB carries, as every card: about 28 MB/s in and
  24 MB/s out (see [xedrivers.md](../xedrivers.md)).
